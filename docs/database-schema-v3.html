1. Patient Identity

Module purpose: Global patient identity across the entire LUCA ecosystem. A patient logs in once via WhatsApp/phone and can link to multiple doctors' records.

PatientAccount

Stores the master identity for every patient in the system. One PatientAccount can be linked to multiple Patient records (one per doctor).

# Field Type Null Default Description
1 id VARCHAR ❌ — Primary key (UUID v7)
2 phone VARCHAR ❌ — Global identifier — WhatsApp number. Unique. Used for OTP login
3 email VARCHAR ✅ — Optional email for notifications. Unique when set
4 passwordHash VARCHAR ❌ — bcrypt/argon2 hash. Used for web portal login
5 fullName VARCHAR ❌ — Patient's full legal name
6 avatarUrl VARCHAR ✅ — Profile picture URL (S3/Cloud Storage)
7 createdAt TIMESTAMP ❌ NOW() Account creation timestamp

Business rules:

  • A patient registers with their phone number (WhatsApp) — this is the universal identifier
  • Email is optional but must be unique when provided
  • The phone number is the global key: a patient can have multiple doctors but only one account

Indexes:

  • PRIMARY KEY (id)
  • UNIQUE (phone)
  • UNIQUE (email) — partial index, nulls not distinct

Zod schema: (not exposed to frontend directly — managed via auth flow)

2. Users & Roles

Module purpose: All professional users: doctors, pharmacy/lab providers, and system administrators. Controls authentication, plan tier, and professional branding.

User

# Field Type Null Default Description
1 id VARCHAR ❌ — Primary key (UUID v7)
2 email VARCHAR ❌ — Login email. Unique
3 passwordHash VARCHAR ❌ — bcrypt/argon2 hash
4 fullName VARCHAR ❌ — Full legal name
5 phone VARCHAR ✅ — Administrative WhatsApp number
6 role UserRole ❌ DOCTOR DOCTOR → PROVIDER → ADMIN
7 isActive BOOLEAN ❌ true Soft-delete / account suspension
8 planType PlanType ❌ FREE FREE → PRO → ENTERPRISE
9 specialty VARCHAR ✅ — e.g. "Cardiología", "Pediatría" (DOCTOR only)
10 logoUrl VARCHAR ✅ — Professional logo for prescriptions/certificates
11 signatureUrl VARCHAR ✅ — Digital signature image URL
12 createdAt TIMESTAMP ❌ NOW() Registration date
13 updatedAt TIMESTAMP ❌ NOW() Last profile update

Business rules:

  • role=DOCTOR → medical professional, can manage patients, write prescriptions, conduct consultations
  • role=PROVIDER → pharmacy or laboratory, must have a linked ProviderProfile
  • role=ADMIN → LUCA platform administrator
  • planType controls feature access: FREE (basic), PRO (full features), ENTERPRISE (multi-clinic, custom branding)
  • specialty, logoUrl, signatureUrl are only relevant for DOCTOR role

Indexes:

  • PRIMARY KEY (id)
  • UNIQUE (email)

Enum: UserRole

Value Description
DOCTOR Medical professional — can manage patients, prescribe, consult
PROVIDER Pharmacy or laboratory — marketplace participant
ADMIN LUCA platform administrator

Enum: PlanType

Value Description
FREE Basic tier — limited patients, no marketplace
PRO Full tier — unlimited patients, marketplace, templates
ENTERPRISE Multi-clinic — custom branding, clinic management, API access

4. Clinical Module

Module purpose: Core clinical workflow: dynamic form templates → consultations with SOAP notes → vital signs → lab requests → appointments.

FormTemplate

Dynamic form builder — doctors can create custom clinical history templates or use global ones by specialty.

# Field Type Null Default Description
1 id VARCHAR ❌ — Primary key (UUID v7)
2 userId VARCHAR ✅ — FK → User. NULL = global template, NOT NULL = personal
3 specialty VARCHAR ✅ — e.g. "Cardiología". For global templates
4 schemaJson JSON ❌ — Array of input definitions: [{name, label, type, options?}]
5 createdAt TIMESTAMP ❌ NOW() Creation timestamp

Business rules:

  • userId=NULL → global template curated by LUCA for a specialty
  • userId=NOT NULL → personal template created by a doctor (drag & drop)
  • schemaJson structure: [{name: "bpm", label: "Frecuencia cardíaca", type: "number", unit: "bpm"}]
  • Supported field types: text, number, select, multiselect, date, textarea, image

Indexes:

  • PRIMARY KEY (id)
  • INDEX (userId)
  • INDEX (specialty) WHERE userId IS NULL

Consultation

The core clinical encounter. Every doctor-patient interaction is a Consultation. Supports dynamic form data via dynamicData.

# Field Type Null Default Description
1 id VARCHAR ❌ — Primary key (UUID v7)
2 userId VARCHAR ❌ — FK → User. Doctor conducting the consultation
3 patientId VARCHAR ❌ — FK → Patient. Patient being seen
4 clinicId VARCHAR ✅ — FK → Clinic. NULL if private practice
5 formTemplateId VARCHAR ✅ — FK → FormTemplate. Template used for this consult
6 date DATETIME ❌ — Consultation date and time
7 status VARCHAR ❌ pending v2: pending → in-progress → completed → cancelled
8 reason VARCHAR ✅ — S (Subjective): Chief complaint / reason for visit
9 physicalExam TEXT ✅ — O (Objective): Physical examination findings
10 diagnosis VARCHAR ✅ — A (Assessment): Diagnosis
11 treatmentPlan TEXT ✅ — P (Plan): Treatment plan
12 dynamicData JSON ✅ — Custom form responses: {bpm: 85, perimetro: 35}

Business rules:

  • SOAP note structure: Subjective (reason), Objective (physicalExam + vital signs), Assessment (diagnosis), Plan (treatmentPlan)
  • dynamicData stores form template responses — keyed by form field name
  • Status workflow: pending (scheduled) → in-progress (doctor started) → completed (finished) → cancelled (not attended)
  • A consultation can have exactly one VitalSign and one LabRequest

Indexes:

  • PRIMARY KEY (id)
  • INDEX (userId, date)
  • INDEX (patientId)
  • INDEX (clinicId)
  • INDEX (status)

5. Prescriptions

Module purpose: Complete prescription workflow: medication catalog → prescription templates → live prescriptions with items.

Medication

Global and personal medication catalog. Global medications are curated by LUCA; doctors can add personal entries.

# Field Type Null Default Description
1 id VARCHAR ❌ — Primary key (UUID v7)
2 userId VARCHAR ✅ — FK → User. NULL = global catalog, NOT NULL = doctor's personal
3 activePrinciple VARCHAR ❌ — Active ingredient, e.g. "Amoxicilina"
4 concentration VARCHAR ❌ — e.g. "500mg", "4mg/ml", "1g"
5 presentation PresentationEnum ❌ — CAPSULA → TABLETA → JARABE → GOTAS → AMPOLLA → CREMA
6 administrationRoute AdministrationRouteEnum ❌ — ORAL → INTRAVENOSA → INTRAMUSCULAR → TOPICA → OFTALMICA
7 commercialName VARCHAR ✅ — Brand name, e.g. "Amoxil"
8 requiresPrescription BOOLEAN ❌ true v3 ⚪ Does it require a medical prescription?
9 contraindications TEXT ✅ — v3 ⚪ Known contraindications
10 isActive BOOLEAN ❌ true Soft-delete / deprecate medication
11 createdAt TIMESTAMP ❌ NOW() Creation
12 updatedAt TIMESTAMP ❌ NOW() Last update

Business rules:

  • Unique constraint: (userId, activePrinciple, concentration, presentation, administrationRoute) — same doctor can't duplicate
  • Global catalog: userId=NULL, visible to all doctors
  • Personal catalog: userId=NOT NULL, visible only to that doctor
  • Seed data: 12 common medications included in DATABASE_PATCH_v2.sql

Indexes:

  • PRIMARY KEY (id)
  • UNIQUE (userId, activePrinciple, concentration, presentation, administrationRoute)
  • INDEX (userId)

Prescription

A live prescription issued by a doctor. Can be linked to a consultation (but not required).

# Field Type Null Default Description
1 id VARCHAR ❌ — Primary key (UUID v7)
2 userId VARCHAR ❌ — FK → User. Prescribing doctor
3 patientId VARCHAR ❌ — FK → Patient
4 consultationId VARCHAR ✅ — FK → Consultation. Optional link. Unique
5 clinicId VARCHAR ✅ — FK → Clinic. NULL if private practice
6 date DATETIME ❌ — Prescription date
7 expirationDate DATETIME ❌ — Expiration date
8 notes VARCHAR ✅ — General notes
9 publicToken VARCHAR ❌ — Shareable token for pharmacy verification. Unique
10 status RxStatus ❌ — ACTIVE → CANCELLED → EXPIRED

Business rules:

  • publicToken is a unique, shareable identifier — patients share this with pharmacies (WhatsApp/link)
  • Status transitions: ACTIVE → CANCELLED (doctor revokes) or ACTIVE → EXPIRED (past expirationDate)
  • If linked to a consultation, it's 1:1 (unique constraint)

Indexes:

  • PRIMARY KEY (id)
  • UNIQUE (consultationId) — partial index, nulls not distinct
  • UNIQUE (publicToken)
  • INDEX (userId)
  • INDEX (patientId)

11. Pharmacy Inventory 🟢 v3

Module purpose: Real-time inventory management for pharmacies. Tracks stock levels, batches, expiration dates, and pricing. Enables accurate quote generation in the marketplace.

PharmacyInventory

# Field Type Null Default Description
1 id VARCHAR ❌ — Primary key (UUID v7)
2 providerId VARCHAR ❌ — FK → ProviderProfile. Pharmacy owning this stock
3 medicationId VARCHAR ❌ — FK → Medication. Which medication
4 stock INT ❌ 0 Current units available
5 minStockAlert INT ✅ 10 Threshold that triggers low-stock alert
6 batchNumber VARCHAR ✅ — Batch/lot number for traceability
7 expirationDate DATE ✅ — Expiration date of this batch
8 unitPrice DECIMAL(10,2) ✅ — Selling price per unit (used for auto-quoting)
9 createdAt TIMESTAMP ❌ NOW() Record creation
10 updatedAt TIMESTAMP ❌ NOW() Last update

Business rules:

  • Unique constraint: (providerId, medicationId, batchNumber) — same pharmacy can't have two records for the same batch
  • When stock <= minStockAlert, the pharmacy receives a "low stock" notification
  • unitPrice is used to auto-generate quote offers in the marketplace
  • batchNumber enables recall tracking in case of medication alerts
  • Pharmacies update stock after each sale/dispensation

Indexes:

  • PRIMARY KEY (id)
  • UNIQUE (providerId, medicationId, batchNumber)
  • INDEX (providerId)
  • INDEX (medicationId)
  • INDEX (expirationDate) WHERE expirationDate IS NOT NULL — for expiration alerts

14. Audit Log 🟢 v3

Module purpose: HIPAA/GDPR-compliant access tracking. Every view, create, update, delete, export, or print of patient data is recorded with user identity, IP address, and action details.

AuditLog

# Field Type Null Default Description
1 id VARCHAR ❌ — Primary key (UUID v7)
2 userId VARCHAR ✅ — FK → User. Who performed the action. NULL if user deleted
3 patientId VARCHAR ✅ — FK → Patient. Whose data was accessed. NULL for non-patient actions
4 action AuditAction ❌ — Type of action performed
5 resource VARCHAR ❌ — Resource identifier, e.g. "Consultation:abc123"
6 resourceType VARCHAR ❌ — Resource type, e.g. "Consultation", "Prescription"
7 details JSONB ✅ — Action metadata: {changedFields: [...], oldValues: {...}}
8 ipAddress VARCHAR ✅ — Client IP address
9 userAgent VARCHAR ✅ — Client user agent string
10 createdAt TIMESTAMP ❌ NOW() Action timestamp

Business rules:

  • Every VIEW of patient data MUST be logged (HIPAA access log requirement)
  • CREATE/UPDATE/DELETE store changed field names and old values in details JSONB for rollback
  • EXPORT logs when data is downloaded (CSV, PDF)
  • PRINT logs when data is printed
  • LOGIN/LOGOUT track session activity
  • userId is SET NULL on user deletion — preserves the audit trail
  • Recommended: partition table by month for performance with large volumes

Indexes:

  • PRIMARY KEY (id)
  • INDEX (userId)
  • INDEX (patientId)
  • INDEX (resourceType, resource)
  • INDEX (createdAt DESC) — time-based queries
